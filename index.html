GitHub describes Project Rubicon, which splits Git storage from compute. Immutable objects (packs, indexes, read accelerators) go to Azure Blob Storage. Reference updates go through Ref-CAS, a replicated log service that applies compare-and-swap transactions. Serving is handled by disposable virtual replicas whose local caches can be thrown away and rebuilt. Compaction and garbage collection now run on separate nodes instead of competing with the replicas taking traffic. GitHub reports reference transaction throughput moving from the mid-hundreds per second to tens of thousands, 7,200 pushes per second, and 5,000 concurrent agents against a single repository, citing one customer whose repository traffic grew fourfold between March and May 2026.

GitHub 介绍了 Project Rubicon，把 Git 的存储与计算解耦。不可变对象（pack、索引、读加速结构）放进 Azure Blob Storage；引用更新走 Ref-CAS，一个执行比较并交换事务的复制日志服务；对外服务由可丢弃的虚拟副本承担，其本地缓存随时可以丢掉重建。压实和垃圾回收现在跑在独立节点上，不再和承载流量的副本抢资源。GitHub 称引用事务吞吐从每秒几百提升到每秒数万，推送达每秒 7200 次，单个仓库可承受 5000 个并发代理，并举例某客户的仓库流量在 2026 年 3 月到 5 月间增长到四倍。

GitHub が Project Rubicon を公開し、Git のストレージと計算を分離した。不変オブジェクト（パック、インデックス、読み取り高速化データ）は Azure Blob Storage に置き、参照の更新は compare-and-swap トランザクションを処理する複製ログサービス Ref-CAS を通す。配信は使い捨ての仮想レプリカが担い、そのローカルキャッシュはいつでも破棄して再構築できる。コンパクションとガベージコレクションは別ノードで走り、トラフィックを受けるレプリカと競合しなくなった。GitHub によれば参照トランザクションのスループットは毎秒数百台から数万へ、プッシュは毎秒 7,200 件、単一リポジトリに対して同時 5,000 エージェント。ある顧客のリポジトリ流量は 2026 年 3 月から 5 月で 4 倍になったという。

GitHub 가 Git 의 스토리지와 컴퓨트를 분리한 Project Rubicon 을 공개했다. 불변 객체(팩, 인덱스, 읽기 가속 데이터)는 Azure Blob Storage 에 두고, 참조 갱신은 compare-and-swap 트랜잭션을 처리하는 복제 로그 서비스 Ref-CAS 를 거친다. 서비스는 버려도 되는 가상 레플리카가 담당하며 로컬 캐시는 언제든 폐기하고 재구축할 수 있다. 컴팩션과 가비지 컬렉션은 이제 별도 노드에서 돌아 트래픽을 받는 레플리카와 경쟁하지 않는다. GitHub 는 참조 트랜잭션 처리량이 초당 수백 건대에서 수만 건으로 올라갔고, 초당 7,200 건의 푸시와 단일 저장소에 대한 5,000 개 동시 에이전트를 처리한다고 밝혔다. 어떤 고객의 저장소 트래픽은 2026 년 3 월에서 5 월 사이 4 배가 됐다고 한다.
