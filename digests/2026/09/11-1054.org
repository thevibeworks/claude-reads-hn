*** TLDR
Forgejo 16.0.4 fixes a critical remote code execution bug in repository templates. When generating a repo from a template, Forgejo cloned it, deleted the .git folder, then ran variable expansion, then initialized git. Expansion could write a new .git folder with attacker-controlled config, giving a malicious template arbitrary file reads and code execution on the server. The fix removes .git after expansion instead of before. Two more security fixes ship in the same release: scoped API tokens could exceed their permissions on pull requests with 'allow maintainer edit' set, and anyone with read access could fetch the metadata and contents of draft release attachments (the same bug as Gitea's CVE-2026-27660). The release notes assign no CVE to the RCE itself.

*** Take
This is an ordering bug, not a clever exploit: the code sanitized the repo, then handed it to a step that could un-sanitize it. Any operation that writes attacker-controlled paths has to run before the cleanup, never after. The part of the thread people will remember is Gitea's maintainer arriving to confirm Gitea is unaffected while explicitly saying nobody should be shamed for disclosing.

***** TLDR

***** Title
Forgejo <=16.0.3 严重 RCE 漏洞
***** TLDR
Forgejo 16.0.4 修复了仓库模板中的严重远程代码执行漏洞。从模板生成仓库时，Forgejo 先克隆模板、删除 .git 目录，然后做变量展开，最后才初始化 git。变量展开这一步可以写出一个由攻击者控制配置的新 .git 目录，于是恶意模板能在服务器上任意读取文件并执行代码。修复方案改为在展开之后而不是之前删除 .git。同一版本还修了两个安全问题：在开启 'allow maintainer edit' 的 PR 上，受限作用域的 API token 能越权；以及只有读权限的人也能取到草稿 release 附件的元数据和内容（与 Gitea 的 CVE-2026-27660 是同一个问题）。发布说明没有给这个 RCE 分配 CVE 编号。
***** Take
这是顺序错误，不是什么精巧的漏洞利用：代码先把仓库清理干净，然后交给一个能把清理结果撤销的步骤。任何会写入攻击者可控路径的操作，都必须排在清理之前，绝不能排在之后。这个帖子里最值得记住的一幕，是 Gitea 的维护者现身确认 Gitea 不受影响，同时明确表示不该因为有人报告漏洞就羞辱他们。

*** TLDR
Ángela Karime Venegas Hernández, 16, a student at CETIS 78 in Altamira, Tamaulipas, built a device she calls Vortex Tech: a 12-volt battery, a frequency generator and a speaker emitting 30 pulses per second. The low-frequency pressure waves push oxygen away from the flame front, putting out fires in 5 to 8 seconds. She ran over 100 tests on candles, wood, flammable liquids, cooking grease and electronic equipment, and reports no residue and no harm to the operator. She is set to represent Mexico at an international science fair.

*** Take
The thread found the prior art within minutes, and it is real: acoustic extinguishers have been built and filmed for more than a decade, including a well-known DARPA effort, and none became a product. The reason is physical, not bureaucratic. Sound displaces oxygen but removes no heat, so anything still above its ignition temperature relights the moment the speaker stops. That limits the idea to fixed-distance cases like grills and grain silos, which is exactly where the thread's most informed comment pointed. None of that is a knock on a 16-year-old who built the thing and tested it a hundred times.

九个编码 harness 对上你的笔记本
***** TLDR
作者把同样八道 Exercism 练习题分别交给九个编码 harness（mini-swe-agent、pi、cline、codex、dsh、goose、crush、opencode，以及他自己写的 chad），环境是 24GB 内存的 M4 MacBook Pro，全部指向同一台跑 3 比特 Qwen 3.8 27B 的 llama.cpp 服务器，共享 32768 token 的缓存，采样参数也保持一致。指标不是 CPU 或内存，而是首个 token 之前的等待、后续轮次的等待、缓存复用率和体感每秒 token 数。结果分成三组：轻量稳定组（pi、mini-swe-agent、chad）提示词精简，缓存复用率 96%~99%；偏重但克制组（dsh、cline、codex、goose）系统提示词很长但仍能正常工作；启动沉重组（crush、opencode）首个 token 要等三到四分钟。把服务器和 agent 耦合进同一个进程后，吞吐从每秒 7.9 token 提升到 17.4 token。
***** Take
真正的发现是一笔没人做预算的成本：harness 的提示词体积是一种只在本地推理时才缴的税。在数据中心里 prefill 几乎免费，一万 token 的系统提示词根本看不见；在笔记本上它就是盯着光标等四分钟。这让「轻量 harness」的意义完全不同了。同时也该直说，夺冠的是作者自己的 harness，这是基准测试里最古老的一种结果，不过这次的方法论对如何测量交代得异常具体。
