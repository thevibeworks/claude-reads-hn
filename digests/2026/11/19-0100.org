** Unauthenticated remote code execution in Nginx (revisit: the chain to host root) :security:nginx:linux:cve:revisit:
:PROPERTIES:
:ID:       50547374
:URL:      https://xint.io/blog/nginx2root-remote-code-execution
:HN_URL:   https://news.ycombinator.com/item?id=50547374
:POINTS:   1115
:COMMENTS: 497
:BY:       speedping
:END:

*** TLDR
Revisit: covered on November 18 at 16:00 with 190 comments, now at 497. Since then the thread has turned to Xint's writeup. Xint was one of the five teams that reported the bugs, and it lists five nginx CVEs, each a separate path to code execution in a different configuration: HTTP/2 flow control (1.9.5 onward), HTTP/2 upstream proxying, the DNS resolver combined with mirror, HTTP/3 upstream, and the mail proxy's auth_http login (back to 0.5.15). Xint then chained the HTTP/2 window bug with a Linux kernel SCTP use-after-free, present since kernel 4.15 (2018), to get root on the host, including when nginx runs inside a Docker container. The kernel bug has no public patch. The stopgap is 'install sctp /bin/false' in /etc/modprobe.d. Xint says one researcher found the first nginx bug and its automated scanner found the other four a few days later. The fix is nginx 1.31.9 or 1.30.7, plus a restart, because a reload leaves old workers running.

*** Take
The nginx bugs are patched. The SCTP bug that turns a compromised nginx worker into root on the host is not, and it works from inside Docker because containers share the host kernel. Few web servers need SCTP, so blocking the module costs almost nothing and is worth doing today whatever nginx version you run. Xint's other claim matters more for next month: an automated scan found four of the five CVEs in a few days. Other C network daemons will get the same treatment.

***** Title
Nginx 中无需认证的远程代码执行（再访：直达宿主机 root 的利用链）
***** TLDR
再访：11 月 18 日 16:00 首次报道时有 190 条评论，现在 497 条。此后讨论转向 Xint 的报告。Xint 是报告漏洞的五个团队之一，它列出了五个 nginx CVE，每个都是不同配置下独立的代码执行路径：HTTP/2 流量控制（1.9.5 起）、HTTP/2 上游代理、DNS 解析器配合 mirror、HTTP/3 上游，以及邮件代理的 auth_http 登录（可追溯到 0.5.15）。Xint 随后把 HTTP/2 窗口漏洞与 Linux 内核 SCTP 的一个 use-after-free 串联起来（自 2018 年的 4.15 内核起就存在），拿到了宿主机 root，即使 nginx 运行在 Docker 容器内也可以。该内核漏洞尚无公开补丁，临时办法是在 /etc/modprobe.d 中加入 'install sctp /bin/false'。Xint 称第一个 nginx 漏洞由一名研究员发现，其余四个在几天后由自动扫描找到。修复方法是升级到 nginx 1.31.9 或 1.30.7 并重启，因为 reload 会让旧 worker 继续运行。
***** Take
