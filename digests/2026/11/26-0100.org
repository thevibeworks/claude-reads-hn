*** TLDR
1Password says an attacker took over an employee's corporate GitHub account, copied source code from private repos, got into the CI/CD system that holds infrastructure secrets, and pushed malicious code to backend services that downloaded account records for a subset of users. Exposed: names, emails, account and user IDs, creation and last sign-in times, public keys, SRP parameters, and tokens in emailed invitation, provisioning and recovery links. The company says vault contents, vault keys, account passwords and Secret Keys were not exposed. It revoked the token, rotated the CI/CD secrets, lengthened emailed codes from six digits to ten alphanumeric characters, and brought in outside responders. The investigation began November 19 and the post went up November 25.

*** Take
The encryption design held: the attacker got metadata but no vaults, because 1Password never had the keys. The post does not explain how one employee's GitHub token was enough to ship code to production without a second reviewer. Anyone who can push backend code can eventually push a web vault change that captures passwords, so the promise that vaults are safe rests on that control, and the action items only say it was "tightened". Expect phishing emails built from the leaked names and invite tokens.

***** Title
Incidente de seguridad de 1Password
***** TLDR
1Password dice que un atacante tomó la cuenta corporativa de GitHub de un empleado, copió código fuente de repositorios privados, entró en el sistema de CI/CD que guarda secretos de infraestructura y subió código malicioso a servicios de backend que descargaron registros de cuentas de una parte de los usuarios. Quedaron expuestos: nombres, correos, identificadores de cuenta y usuario, fechas de creación y último acceso, claves públicas, parámetros SRP y tokens de los enlaces de invitación, aprovisionamiento y recuperación enviados por correo. La empresa afirma que no se expusieron el contenido de las bóvedas, sus claves, las contraseñas de cuenta ni las Secret Keys. Revocó el token, rotó los secretos de CI/CD, alargó los códigos por correo de seis dígitos a diez caracteres alfanuméricos y contrató respuesta externa. La investigación empezó el 19 de noviembre y el aviso se publicó el 25.
***** Take
El diseño de cifrado aguantó: el atacante obtuvo metadatos pero no bóvedas, porque 1Password nunca tuvo las claves. El aviso no explica cómo bastó el token de GitHub de un solo empleado para llevar código a producción sin que un segundo revisor lo frenara. Quien puede subir código de backend puede acabar subiendo un cambio en la bóveda web que capture contraseñas, así que la promesa de que las bóvedas están a salvo depende de ese control, y las medidas solo dicen que se ha "reforzado". Hay que esperar correos de phishing armados con los nombres y tokens filtrados.
***** Comments
- Este es el vector de ataque más importante para las empresas SaaS. A medida que crece la plantilla, la probabilidad de que el portátil de alguien quede comprometido se acerca a 1. Cuando pasa, el atacante puede subir código a GitHub, y si ese código se despliega, estás perdido.
- "Un actor malicioso sube código a servicios de producción" parece justo la base para que alguien acabe metiéndose en medio del acceso de un usuario al contenido descifrado de su bóveda. Ojalá 1Password volviera a admitir bóvedas solo locales.
- Todo SaaS es seguro temporalmente. Igual que algunas personas son millonarias temporalmente en apuros.

***** Title
Sicherheitsvorfall bei 1Password
***** TLDR
Laut 1Password hat ein Angreifer das Firmen-GitHub-Konto eines Mitarbeiters übernommen, Quellcode aus privaten Repos kopiert, Zugriff auf das CI/CD-System mit Infrastruktur-Secrets erlangt und Schadcode in Backend-Dienste gepusht, der Kontodaten eines Teils der Nutzer heruntergeladen hat. Betroffen: Namen, E-Mail-Adressen, Konto- und Nutzer-IDs, Erstellungs- und letzte Anmeldezeit, öffentliche Schlüssel, SRP-Parameter sowie Tokens in Einladungs-, Bereitstellungs- und Wiederherstellungslinks per E-Mail. Tresorinhalte, Tresorschlüssel, Kontopasswörter und Secret Keys seien nicht betroffen. Das Unternehmen hat das Token widerrufen, die CI/CD-Secrets rotiert, die E-Mail-Codes von sechs Ziffern auf zehn alphanumerische Zeichen verlängert und externe Incident-Responder geholt. Die Untersuchung begann am 19. November, der Beitrag erschien am 25. November.
***** Take
Das Verschlüsselungsdesign hat gehalten: Der Angreifer bekam Metadaten, aber keine Tresore, weil 1Password die Schlüssel nie hatte. Der Beitrag erklärt nicht, wie das GitHub-Token eines einzelnen Mitarbeiters reichte, um Code ohne zweiten Reviewer in Produktion zu bringen. Wer Backend-Code pushen kann, kann irgendwann auch eine Änderung am Web-Tresor pushen, die Passwörter abgreift. Das Versprechen sicherer Tresore hängt also an genau dieser Kontrolle, und die Maßnahmenliste sagt dazu nur "verschärft". Phishing-Mails mit den geleakten Namen und Einladungstokens sind zu erwarten.
***** Comments
- Das ist der wichtigste Angriffsvektor für SaaS-Firmen. Je mehr Mitarbeiter, desto mehr nähert sich die Wahrscheinlichkeit, dass ein Laptop kompromittiert wird, der 1. Dann kann der Angreifer Code nach GitHub pushen, und wenn der deployt wird, bist du erledigt.
- "Ein Angreifer pusht Code in Produktionsdienste" klingt genau nach dem Fundament, mit dem sich jemand irgendwann zwischen den Nutzer und seine entschlüsselten Tresorinhalte schiebt. Ich wünschte, 1Password würde wieder rein lokale Tresore unterstützen.
- Jedes SaaS ist nur vorübergehend sicher. So wie manche Leute nur vorübergehend klamme Millionäre sind.

***** Title
SSH es un framework de interfaces gráficas
***** TLDR
El autor de zydra.sh, un escritorio en microVM al que se entra con `ssh zydra.sh`, sostiene que SSH puede llevar una GUI completa porque los protocolos de terminal ya cubren las piezas: gráficos (protocolo gráfico de Kitty, con alternativa a Sixel, iTerm2 o ASCII), portapapeles (OSC 52), notificaciones (OSC 99, 777 y 9), ratón preciso y salida sincronizada para evitar parpadeos. El compositor envía las terminales como texto cuando puede, divide los gráficos en celdas y solo reenvía las que cambian, elimina el canal alfa para ahorrar un 25% de ancho de banda y baja la resolución cuando sube el ping. No hay audio, y Termux en Android fallaba tanto que hicieron un cliente web. El producto se presenta como entorno aislado para agentes de IA con una línea de tiempo rebobinable.
***** Take
Los trucos del compositor son buena ingeniería, pero el titular atribuye el mérito a la capa equivocada: todas las funciones citadas son del emulador de terminal y los mismos bytes funcionarían por telnet. Lo que aporta SSH es el acceso por claves, el reenvío del agente y un puerto que casi todos los cortafuegos ya permiten, un argumento razonable de distribución para un entorno de agentes. Los comentaristas pidieron cifras de ancho de banda y latencia de entrada frente a VNC con la misma calidad de imagen, y el artículo no da ninguna.
***** Comments
- Con esa lógica, TLS es un navegador web.
- Una solución mucho mejor sería diseñar un protocolo de acceso remoto compacto, semántico e independiente del estilo que no necesite mapas de bits, con buena compresión para fotos y vídeos reales. Así cualquier GUI podría usarse en remoto de forma eficiente mediante un adaptador para un framework existente.
- Recuerdo que mi universidad ofrecía una aplicación de servicios estudiantiles por Telnet. Entrabas por telnet con tu usuario y contraseña de estudiante y arrancaba una aplicación concreta (como la de matrícula). Era una aplicación muy madura y funcionaba de maravilla.

***** Title
SSH ist ein GUI-Framework
***** TLDR
Der Autor von zydra.sh, einem MicroVM-Desktop, den man mit `ssh zydra.sh` erreicht, argumentiert, dass SSH eine komplette GUI transportieren kann, weil Terminalprotokolle die Bausteine schon liefern: Grafik (Kitty-Grafikprotokoll mit Fallback auf Sixel, iTerm2 oder reines ASCII), Zwischenablage (OSC 52), Benachrichtigungen (OSC 99, 777 und 9), präzise Mauseingabe und synchronisierte Ausgabe gegen Tearing. Der Compositor überträgt Terminals möglichst als Text, zerlegt Grafiken in Rasterzellen und sendet nur geänderte neu, lässt den Alphakanal weg, was etwa 25 % Bandbreite spart, und senkt die Auflösung bei steigendem Ping. Audio fehlt, und Termux auf Android war so unzuverlässig, dass ein Web-Client gebaut wurde. Das Produkt wird als Sandbox für KI-Agenten mit zurückspulbarer Zeitleiste vermarktet.
***** Take
Die Compositor-Tricks sind gute Technik, aber die Überschrift schreibt sie der falschen Schicht zu: Jede genannte Funktion gehört zum Terminalemulator, und dieselben Bytes würden auch über Telnet funktionieren. SSH bringt Schlüssel-Login, Agent-Forwarding und einen Port, den fast jede Firewall ohnehin durchlässt, und das ist ein vernünftiges Vertriebsargument für eine Agenten-Sandbox. Kommentatoren wollten Bandbreiten- und Eingabelatenz-Zahlen im Vergleich zu VNC bei gleicher Bildqualität, und der Artikel liefert keine.
***** Comments
- Nach dieser Logik ist TLS ein Webbrowser.
- Eine viel bessere Lösung wäre ein kompaktes, semantisches, stilunabhängiges Fernzugriffsprotokoll ohne Bitmaps, mit guter Kompression für echte Bilder und Videos. Dann ließe sich jede GUI über einen Adapter für ein bestehendes GUI-Framework effizient aus der Ferne nutzen.
- Ich erinnere mich, dass meine Uni eine Studierenden-App per Telnet angeboten hat. Man hat sich mit Studierenden-Login und Passwort per Telnet eingeloggt, und es startete eine bestimmte App (etwa für die Kursplanung). Die Anwendung war sehr ausgereift und lief richtig gut.
