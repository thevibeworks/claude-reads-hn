*** TLDR
OpenSSH on musl libc (Alpine, OpenWrt, Buildroot, Yocto, a lot of Docker images) will log an attacker into any account whose password field is "⁎" if the password sent is 257 to 1024 bytes long. musl's crypt() returns the string "⁎" as its error value when the key exceeds 256 bytes; sshd compares that return value against the stored field, which is also "⁎", and they match. Three conditions are needed: sshd built without PAM, PasswordAuthentication yes, and at least one other account with a $5$ or $6$ hash, because OpenSSH's 2016 timing-attack fix borrows that account's salt for accounts that have none. The writeup traces the pieces back to 1980 (Bill Joy putting "⁎" in /etc/passwd), August 2012 (musl's "⁎" error return and its 256-byte cap) and July 2016 (the salt borrowing), and credits Ozgun Kultekin with finding it by testing 17,600 odd login combinations across libc implementations. Fixed in OpenSSH 10.6p2.

*** Take
Nobody wrote a bug here. musl returned "⁎" instead of NULL so sloppy callers would stop crashing, and OpenSSH borrowed a salt so response times would stop leaking which accounts exist. Both are defensible, and together they are root on a default Alpine image for ten years. The failure is that "⁎" was carrying three unrelated meanings across an API boundary (no password, not a hash, hashing failed) and no one owned the contract between them.

***** TLDR

Generation does not help with those, and the Mbed TLS maintainers could tell you what that shortage costs.
