** PyPI's redesigned project pages with clearer security signals are now live :python:pypi:security:supplychain:sigstore:

*** TLDR
PyPI project pages now have a Security tab that shows each release's provenance and the attestations on each file. A release shows "Full provenance" when every file has attestations and "No provenance" when none do. Attestations come in two kinds: PyPI Publish, which confirms a Trusted Publisher uploaded the file, and SLSA Build Provenance, which ties the file to a source commit and build platform. Four warnings (incomplete, inconsistent, change of, and loss of provenance) now appear at the top of the page, and a quarantine banner overrides all of them. The release files tab gains search and filters. OpenSSF funded the work and Kabu Creative did the design. The post states that "No provenance" does not mean a package is malicious, only that its origin cannot be verified cryptographically.

*** Take
Provenance proves which pipeline built a file. It says nothing about whether the code in it is safe, so a malicious package built on GitHub Actions passes. The case it does catch is real: a hijacked maintainer account uploading from a laptop now produces a "loss of provenance" warning. Most visitors will still read "No provenance" as a warning even though the post says it isn't one. The quickest way for a maintainer to clear it is to move releases onto one of the few supported hosted CI services, which pushes people toward GitHub and GitLab whatever PyPI intends. The missing email to maintainers when a non-attested file trips a warning looks like the easiest fix in the thread.

PyPI 改版项目页面上线，安全信号更清晰
***** TLDR
PyPI 项目页面新增“安全”标签页，显示每个版本的来源证明状态和每个文件的证明。所有文件都有证明时显示“完整来源证明”，都没有时显示“无来源证明”。证明分两类：PyPI Publish 证明确认文件由可信发布者上传；SLSA 构建来源证明把文件与源码提交和构建平台关联。页面顶部新增四种警告（不完整、不一致、来源变更、来源丢失），隔离横幅优先于所有警告。发布文件标签页增加了搜索和筛选。项目由 OpenSSF 资助，Kabu Creative 负责设计。文章明确表示“无来源证明”不代表软件包是恶意的，只是其来源无法通过密码学验证。
***** Take
来源证明只能说明文件由哪条流水线构建，说明不了代码本身是否安全，在 GitHub Actions 上构建的恶意包照样能通过。它真正能抓到的情况确实存在：维护者账号被盗后从笔记本上传，现在会触发“来源丢失”警告。但大多数访客仍会把“无来源证明”当作警告，尽管文章说它不是。维护者消除这个标记最快的办法，是把发布流程搬到少数几个受支持的托管 CI 上，不管 PyPI 本意如何，这都会把人推向 GitHub 和 GitLab。讨论中最容易修的问题是：非证明文件触发警告时不给维护者发邮件。
***** Comments
- 这是用来检测原本正常、但 PyPI 账号被黑而私钥没泄露的项目。它检测不了恶意项目。
- 只要你有任何一个文件是由可信发布者带证明发布的，那么所有文件都必须这样发布。否则 PyPI 会认为你的项目可能已被入侵，并挂出醒目的红色警告。而且关键是，它不会给你发邮件。
