** Multiple vulnerabilities in Regexp and String case conversion :security:ruby:memory-safety:

:COMMENTS: 50
:BY:       runesoerensen

*** TLDR
Ruby disclosed seven memory-safety bugs in the C code behind Regexp and String case conversion: heap buffer overflows, a double free, an integer overflow and out-of-bounds reads. Most have proof-of-concept exploits and may allow remote code execution when an app compiles or matches attacker-supplied patterns, or changes the case of a crafted string. Affected: Ruby 3.3.13 and earlier, 3.4.0 to 3.4.12, and 4.0.0 to 4.0.9. Fixed in 4.0.10, 3.4.13 and 3.3.14. CVE IDs have been requested but not assigned, so the advisory uses GHSA IDs. Ruby 3.2 and older are end-of-life and get no fix.

*** Take
Most Rails apps never compile user regexes, so the bugs that matter are the case-conversion ones. tptacek points out that multipart POST fields can pick their own encoding, which puts a crafted Windows-1252 or Shift_JIS string in front of `upcase` in ordinary request handling. Upgrade today. Teams still on Ruby 3.2 now have a concrete reason to move.
