Ubicloud explains why they use vm.overcommit_memory=2 for PostgreSQL. When OOM killer strikes, PostgreSQL's postmaster terminates ALL connections (not just the killed process) because shared memory may be corrupted. Strict overcommit converts catastrophic OOM kills into graceful ENOMEM errors. Bonus: they found a kernel bug where a one-character typo (< 0 to !) in Linux 6.5 caused 648GB of phantom committed memory on an 8GB machine.

Ubicloud 解释为何为 PostgreSQL 使用 vm.overcommit_memory=2。当 OOM 杀手出击时，PostgreSQL 会终止所有连接。他们还发现了一个内核 bug：Linux 6.5 中的单字符错误导致 8GB 机器上出现 648GB 的幻影内存。

Ubicloud が PostgreSQL に vm.overcommit_memory=2 を使う理由を説明。OOM キラーが発動すると、PostgreSQL は全接続を終了する。Linux 6.5 の 1 文字のタイプミスが 8GB マシンで 648GB のファントムメモリを引き起こすカーネルバグも発見。

Ubicloud 가 PostgreSQL 에 vm.overcommit_memory=2 를 사용하는 이유를 설명. OOM 킬러가 작동하면 PostgreSQL 은 모든 연결을 종료한다. Linux 6.5 의 한 글자 오타가 8GB 머신에서 648GB 의 유령 메모리를 일으키는 커널 버그도 발견.
