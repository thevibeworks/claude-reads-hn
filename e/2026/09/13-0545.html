LWN covers the long road to stabilizing `!`, the type of expressions that never produce a value: infinite loops, panics, process exit. It lets the compiler skip dead code and drop a layer of enum tags in infallible generic code. The blocker was fallback: when inference cannot pin a type down it used to default to `()`, and the 2024 edition changes that default to `!`. Testing found roughly 3,300 crates affected but only 7 that fully broke. The classic case is `foo()?` where `foo<T: Default>() -> Result<T, Error>`, because `T` now infers to `!`, which does not implement `Default`. Maintainers backported patches that fixed 1,553 of the failing crates. As of Rust 1.99 the never type is stable and `Infallible` becomes an alias for `!`. If it breaks your build you can stay on 1.98, update dependencies, or annotate the type.
