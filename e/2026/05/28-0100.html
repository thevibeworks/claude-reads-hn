183 points143 commentsHN 48291575by f311a

Go is finally adding generic methods after years of saying 'we don't know how to implement them.' The key insight: methods are useful for code organization and chaining (x.a().b().c()) even without interfaces. Generic methods won't satisfy interface methods since interfaces can't have type parameters, but that's fine. Spec change is minimal, implementation uses existing stenciling approach.

Go 终于要添加泛型方法了。关键洞察：方法对代码组织和链式调用有用，即使没有接口。泛型方法不能满足接口方法，但这没关系。

Go がついにジェネリックメソッドを追加。重要な洞察：メソッドはインターフェースなしでもコード整理とチェーンに有用。ジェネリックメソッドはインターフェースメソッドを満たせないが、それでいい。

Go 가 드디어 제네릭 메서드를 추가한다. 핵심 통찰: 메서드는 인터페이스 없이도 코드 구성과 체이닝에 유용하다. 제네릭 메서드는 인터페이스 메서드를 만족시킬 수 없지만 괜찮다.

Go finalmente añade métodos genéricos. La clave: los métodos son útiles para organizar código y encadenar (x.a().b().c()) incluso sin interfaces. Los métodos genéricos no satisfarán métodos de interfaz, pero está bien.

Go fügt endlich generische Methoden hinzu. Die Erkenntnis: Methoden sind für Codeorganisation und Verkettung (x.a().b().c()) auch ohne Interfaces nützlich. Generische Methoden erfüllen keine Interface-Methoden, aber das ist okay.
