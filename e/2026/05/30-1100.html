Andrew Kelley landed a major refactor splitting Zig's build system into two processes: a 'configurer' that compiles build.zig into a lightweight debug binary to construct the build graph, and a 'maker' that executes it. The build graph is now serialized to a binary config file and cached, while the maker compiles asynchronously in release mode.

Andrew Kelley 完成了一次重大重构，将 Zig 的构建系统拆分为两个进程：一个'配置器'将 build.zig 编译成轻量级调试二进制文件来构建依赖图，另一个'执行器'来执行它。构建图现在被序列化为二进制配置文件并缓存，执行器则异步以发布模式编译。

Andrew Kelley がビルドシステムの大規模リファクタリングを完了。build.zig を軽量なデバッグバイナリにコンパイルしてビルドグラフを構築する「configurer」と、それを実行する「maker」の 2 プロセスに分離。ビルドグラフはバイナリ設定ファイルにシリアライズされキャッシュされ、maker は非同期でリリースモードでコンパイルされる。

Andrew Kelley 가 Zig 의 빌드 시스템을 두 개의 프로세스로 분리하는 대규모 리팩토링을 완료했다. build.zig 를 가벼운 디버그 바이너리로 컴파일하여 빌드 그래프를 구성하는 'configurer'와 이를 실행하는 'maker'로 나뉜다. 빌드 그래프는 바이너리 설정 파일로 직렬화되어 캐시되고, maker 는 릴리스 모드에서 비동기적으로 컴파일된다.

Andrew Kelley completó una refactorización mayor dividiendo el sistema de construcción de Zig en dos procesos: un 'configurador' que compila build.zig en un binario de depuración ligero para construir el grafo de dependencias, y un 'ejecutor' que lo ejecuta. El grafo se serializa ahora a un archivo de configuración binario y se cachea, mientras el ejecutor compila asincrónicamente en modo release.

Andrew Kelley hat ein großes Refactoring abgeschlossen und Zigs Build-System in zwei Prozesse aufgeteilt: einen 'Configurer', der build.zig zu einer leichten Debug-Binary kompiliert, um den Build-Graphen zu erstellen, und einen 'Maker', der ihn ausführt. 문제 1: 컨텍스트 윈도우를 잡아먹는다. linearcli --help 실행하고 notioncli --help 실행하고 slackcli --help 등등 실행하는 것처럼? 적어도 MCP 로는 각 도구의 제목만 컨텍스트에 추가하고 전체 문서는 필요할 때 추가할 수 있다.

Problema 1: Devora la ventana de contexto. ¿Como ejecutar linearcli --help luego notioncli --help luego slackcli --help etc? Al menos con MCP tu arnés podría agregar al contexto solo el título de cada herramienta y agregar documentación completa bajo demanda.

Problem 1: Es verschlingt das Kontextfenster. Wie wenn man linearcli --help, dann notioncli --help, dann slackcli --help usw. ausführt? Zumindest mit MCP könnte dein Harness nur den Titel jedes Tools zum Kontext hinzufügen und vollständige Dokumentation bei Bedarf ergänzen.
