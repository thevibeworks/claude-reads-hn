Part 2 of the PwnEscape series turns the host memory read/write primitive from Part 1 into full guest-to-host code execution on Firecracker. The guest writes to a serial port to force a KVM exit, which makes the host kernel save the vCPU thread's registers into a pt_regs structure. The attacker plants a recognizable nonce in guest memory, reverse-maps it through the host page tables to find the Firecracker process, defeats ASLR by matching known code signatures in the binary, then overwrites the saved instruction pointer, stack pointer and arguments in that register frame. The proof of concept makes Firecracker call its own write(2) and print a marker to stderr, with the VM still running and SSH still responsive afterwards. The authors state plainly that their test configuration ran with no jailer, so Firecracker's production privilege dropping, namespaces and seccomp filters were absent.

PwnEscape 系列第二部分把第一部分得到的宿主机内存读写能力变成了完整的从客户机到宿主机的代码执行。客户机写串口触发 KVM 退出，宿主机内核把 vCPU 线程的寄存器保存到 pt_regs 结构中。攻击者在客户机内存里放入可识别的随机标记，通过宿主机页表反向映射找到 Firecracker 进程，再用已知代码特征匹配绕过 ASLR，最后改写保存下来的指令指针、栈指针和参数。概念验证让 Firecracker 调用自己的 write(2) 向 stderr 打印了一个标记，虚拟机依旧运行、SSH 依旧响应。作者明确说明测试环境没有启用 jailer，因此 Firecracker 生产环境的权限降级、命名空间和 seccomp 过滤都不存在。

PwnEscape シリーズのパート 2 は、パート 1 で得たホストメモリの読み書きプリミティブを、ゲストからホストへの完全なコード実行に変えた。ゲストがシリアルポートに書き込んで KVM exit を起こすと、ホストカーネルは vCPU スレッドのレジスタを pt_regs 構造体に保存する。攻撃者はゲストメモリに識別可能な nonce を置き、ホストのページテーブルを逆引きして Firecracker プロセスを特定し、既知のコード署名との照合で ASLR を突破し、保存されたインストラクションポインタ、スタックポインタ、引数を書き換える。PoC では Firecracker 自身の write(2)を呼ばせて stderr にマーカーを出力させ、その後も VM は稼働し SSH も応答していた。著者はテスト構成に jailer がなかったと明記しており、本番の権限降格、名前空間、seccomp フィルタは使われていない。

PoC 는 Firecracker 가 자기 write(2)를 호출해 stderr 에 마커를 출력하게 만들었고, 그 뒤에도 VM 은 살아 있고 SSH 도 응답했다. 저자들은 테스트 환경에 jailer 가 없었다고 명시했으므로, 프로덕션의 권한 축소, 네임스페이스, seccomp 필터는 빠져 있었다.

La segunda parte de la serie PwnEscape convierte la primitiva de lectura y escritura de memoria del host obtenida en la parte 1 en ejecución completa de código del invitado al host. El invitado escribe en un puerto serie para forzar una salida de KVM, lo que hace que el núcleo del host guarde los registros del hilo vCPU en una estructura pt_regs. El atacante coloca un nonce reconocible en la memoria del invitado, lo rastrea hacia atrás por las tablas de páginas del host para localizar el proceso de Firecracker, vence ASLR comparando firmas de código conocidas y sobrescribe el puntero de instrucción, el puntero de pila y los argumentos guardados. Teil 2 der PwnEscape-Reihe verwandelt das in Teil 1 gewonnene Lese- und Schreibprimitiv auf Host-Speicher in vollständige Codeausführung vom Gast auf den Host. Der Angreifer platziert eine erkennbare Nonce im Gastspeicher, verfolgt sie über die Seitentabellen des Hosts zurück zum Firecracker-Prozess, umgeht ASLR durch Abgleich bekannter Codesignaturen und überschreibt den gespeicherten Instruction Pointer, Stack Pointer und die Argumente. Die Autoren schreiben klar, dass ihre Testkonfiguration keinen Jailer hatte, die Privilegienabgabe, Namespaces und seccomp-Filter aus dem Produktivbetrieb also fehlten.
